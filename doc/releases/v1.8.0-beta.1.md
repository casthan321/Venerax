# Venera Community 1.8.0 Beta 1

这是 Venera Community 1.8 系列的首个公开 Beta，重点改进“漫画源”页面的仓库管理、来源更新安全性与跨设备配置持久化。它不是上游官方 Venera 发布，而是用于收集实际设备反馈的社区测试版本。

> Beta 提示：漫画源脚本属于可执行代码。请只添加你信任的仓库，并在安装或切换来源前核对仓库名称、清单地址和最终下载主机。升级前建议先在旧版本中导出一份本地备份。

## 同一界面管理多个漫画源仓库

- 保留原有“漫画源 → 仓库地址”界面，不再额外增加一个相互割裂的仓库管理页。
- 顶部仓库卡片现在可以保存多个 `index.json` 地址，并通过下拉框切换当前仓库。
- 下方列表只显示当前选中仓库提供的漫画源，不会把多个仓库的条目混在一起。
- 支持新增、重命名、编辑地址、启用/禁用、测试连接、刷新、调整顺序和删除仓库。
- 禁用的仓库仍可被选中和编辑，重新启用后即可继续加载。
- 当前选择、仓库顺序和启用状态会立即保存，重启应用后恢复上次选择。
- 仓库操作和源列表都适配窄屏 Android、Windows 窗口缩放、键盘操作、Tooltip 与读屏语义。

## 兼容、迁移与同步

- 首次升级会把旧版中有效的 HTTPS `comicSourceListUrl` 迁移为一个已启用仓库；原官方地址继续使用官方 CDN。
- 旧版中仍可安全识别、且不含凭据或敏感查询的 HTTP 地址不会被静默覆盖，而会保留为待检查配置；含凭据、敏感参数或无法解析的异常地址不会进入新仓库列表。新建仓库要求使用 HTTPS。
- 新旧配置保留兼容镜像，降低旧客户端写入设置后再次升级造成仓库列表丢失的风险。
- 仓库列表可以随普通设置同步；如果用户将仓库设置加入“不同步字段”，旧兼容字段也会一并排除。
- 导入不含新绑定信息的旧备份时会清理不再可靠的仓库绑定，避免同 key 的旧脚本被错误仓库接管更新。
- 清单同时兼容 `fileName` 与历史文档中的 `filename` 字段，相对脚本地址以仓库最终清单地址为基准解析。

## 仓库与脚本安全

- 仓库清单和脚本使用独立网络客户端，不携带应用中的登录 Cookie、Authorization 或 Cloudflare 会话。
- 仓库请求始终强制验证 HTTPS 证书；即使用户为普通漫画站点开启“忽略错误证书”，也不会影响仓库供应链。
- 每次 HTTPS 重定向都会重新校验，拒绝降级到 HTTP、凭据 URL、敏感查询参数、循环及过多跳转。
- 清单和脚本采用流式大小限制；格式错误条目只隔离自身，一个仓库失败不会遮蔽其他仓库。
- 首次安装、切换仓库以及最终下载主机发生变化时都会显示信任确认，不会静默执行来自新主机的脚本。
- 已安装源会记录仓库、脚本地址、最终地址和版本；同 key 的其他仓库不能自动接管更新。
- 跨仓库切换同 key 来源时默认隔离旧源账号与私有数据，避免把登录信息直接交给新脚本。
- 安装、切换和更新使用互斥操作与持久恢复日志；写文件、保存绑定或重新加载失败时会回滚旧脚本、旧数据和旧设置。
- 每次解析的漫画源都带有独立运行代次。旧页面、延迟回调和旧 JS 定时任务在来源被替换后无法调用新脚本，也不能读取或重写新源的私有数据。

## 更新与错误处理

- 自动检查会遍历全部已启用仓库；单个仓库失败会分别记录并继续，不会因一个地址不可用而中止其他仓库。
- 更新候选必须同时匹配已绑定仓库、脚本 URL、source key 和清单版本；下载脚本声明不一致时拒绝替换。
- 手动更新在应用重启后仍优先使用持久仓库绑定，不会退回脚本自行声明的未知更新地址。
- 快速切换或刷新仓库时，旧请求结果不会覆盖当前选择；取消下载后也不会继续弹出信任或安装对话框。
- 仓库配置保存失败会恢复原选择和原配置，避免下拉框进入无法继续操作的状态。

## 安装与升级

- Android Community 包名仍为 `io.github.casthan321.venera`；使用正式 Community 签名的 1.7.0 可以覆盖升级，自编译或其他签名的 APK 不能原位覆盖。社区版仍可与上游官方包 `com.github.wgh136.venera` 共存。
- 本 Beta 使用构建号 `180`：universal、armeabi-v7a、arm64-v8a、x86_64 APK 的 versionCode 分别为 1800、1801、1802、1803，均高于 1.7.0 正式版。
- Android 提供 universal、arm64-v8a、armeabi-v7a 与 x86_64 APK。现代手机通常选择 arm64-v8a；不确定设备架构时选择 universal。
- Windows 提供 x64 安装器与便携 ZIP。安装器可从 Venera Community 1.7.0 原位升级；便携 ZIP 需要完全退出旧程序后手动替换，或解压到新目录。安装器没有商业 Authenticode 证书，SmartScreen 可能显示未知发布者，请从本 Release 下载并核对 SHA-256。
- 1.7.0 正式版用户默认不会被引导到 Beta；希望参与测试的用户可以手动安装，或在“设置 → 关于”中开启“接收 Beta 测试版更新”。

## 已知限制

- 页面一次只显示当前选中仓库的漫画源；后台更新检查仍会检查所有已启用仓库。
- 禁用或删除仓库不会自动卸载已经安装的漫画源，但这些源将停止从该仓库获取更新，直到重新配置或明确切换仓库。
- 当前不支持需要 Cookie、Authorization、token 或带密钥查询参数的私有仓库；这类凭据不会被保存到仓库设置中。
- 仓库中的漫画源脚本没有独立数字签名。登录、签到、收藏和阅读能力仍取决于第三方脚本及对应站点接口，请只使用可信仓库。
- 同步仓库设置不等于同步已安装的 JS 文件、登录账号或来源私有数据；新设备仍需逐个确认并安装来源。
- 仓库索引最大 1 MiB、最多 1000 个条目，单个来源脚本最大 2 MiB。
- 取消仓库脚本下载会阻止后续信任确认和安装，但暂时不会立即终止已经发出的网络传输。

## 建议重点测试

1. 保存两个或更多仓库，反复切换、重启应用，确认选择、顺序与启用状态都能恢复。
2. 在 Android 窄屏和 Windows 不同缩放下新增、编辑、禁用、删除和刷新仓库，确认没有布局溢出。
3. 让一个仓库离线或返回坏清单，确认其他仓库仍可使用，并能看到明确错误状态。
4. 安装两个仓库中不同 key 的来源，以及显式切换同 key 来源，确认信任提示、账号隔离和失败回滚符合预期。
5. 测试相对脚本地址、跨 HTTPS CDN 重定向、取消下载、更新版本不匹配及最终主机变化提示。
6. 测试设置同步、本地导出/导入和旧版单仓库配置迁移。

## 验证与反馈

发布流水线会在公开前强制执行 Dart 格式检查、全仓 `flutter analyze`、完整 Flutter 测试、Android 永久签名证书指纹校验、四个 APK 的签名与 SHA-256 验证、Windows x64 Release/安装器构建以及双平台产物校验。任一必需步骤失败都不会公开 Release。

应用界面、仓库保存、迁移、崩溃、更新绑定或回滚问题可以反馈到 Venera Community 仓库。某个具体漫画源的登录、签到、内容、网站可用性或脚本规则问题，请联系对应仓库或来源维护者。

反馈时请附上平台、系统版本、应用版本、仓库清单地址的公开主机、操作步骤和“设置 → Debug”中的相关脱敏日志。请不要公开完整私有仓库地址、Cookie、账号密码、Authorization、访问令牌、带签名参数的下载链接或代理密码。
